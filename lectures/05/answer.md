- やったこと（変更したファイル・設定・処理、または設計した取得方法）：
  - `app/retrieval.py` に `search_with_neighbors(query, window)` を足した。`search()` の結果に、同じ `document_id` の前後 `window` 枚のページの本文を付けて返す
    - ページの前後は `load_pages()` の並び（資料 → 章 → ページの順）で決める。別の資料のページは付けない
    - ヒットしたページには `role: "hit"` と `distance`、付け足したページには `role: "neighbor"` と `neighbor_of`（どのヒットの隣か）を付ける。付け足したページには距離が無いので、`distance` は入れない
    - 同じページは1回だけ返す。隣のページが別のヒットでもある場合は、ヒットとして返す
    - 並びは、ヒットの順に「前のページ → ヒット → 次のページ」。続けて読めるようにした
  - `app/config.py` に `RAG_NEIGHBOR_WINDOW`（環境変数 `AIE_RAG_NEIGHBORS`、既定 0）を足し、`tools.search_materials` は 1 以上のときだけ `search_with_neighbors` を使うようにした。既定では変更前と同じ動きになるので、同じコードで変更前後を比べられる
  - `search()` そのものは変えていない。`search_graph()` が `search()` の結果を入口にして `distance` を読むことと、STEP 2 の `python -m app.retrieval` の表示が同じ関数を使うため
  - `python -m app.retrieval` に `--neighbors N` を足し、検索だけでも前後ページ付きの結果を見られるようにした
  - `tests/test_retrieval_neighbors.py`：埋め込み API を呼ばずに、0 のときはヒットだけ、前後ページが読む順に付く、資料をまたがない、重複しない、を確かめた。`uv run pytest` は 25 件すべて通った
