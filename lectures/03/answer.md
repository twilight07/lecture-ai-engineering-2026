## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(title, content)` を作った。`learning_log/` に `日時-題名.md` で保存する。題名のうち、ファイル名に使えない文字（`/` や `.` など）は `-` に置き換えるので、`../` を含む題名でもフォルダの外には書かない。同じ名前のファイルがあっても上書きしない
  - `app/agent.py` で `requires_approval=True` を付けて登録し、`output_type=[str, DeferredToolRequests]` にした
  - CLI に `run_with_approval()` を足した。結果が `DeferredToolRequests` のあいだは、`approvals` のツール呼び出しごとに引数を表示して `[y/N]` を聞く。`y` なら `True`、それ以外なら `ToolDenied("利用者が保存を断りました…")` を `DeferredToolResults` に入れ、`message_history=result.all_messages()` と一緒に `run_sync` をもう一度実行する
  - `tests/test_learning_log.py`：API を使わずに、TestModel で次を確かめた
    - 承認されるまで保存されない
    - `y` で1件保存される
    - `n` と空の入力では保存されず、断ったことがモデルに返る
    - フォルダの外に書かない
  - 全体で `uv run pytest -q` → 25 passed
- 結果：
  - 承認（`y`）：「LoRAとQLoRAの違いを調べて、学習の記録として保存して」→ `search_glossary` で LoRA と QLoRA を1回ずつ検索 → `save_learning_log` が承認待ちで止まり、題名と本文が表示される → `y` で `learning_log/20261109-163700-LoRAとQLoRAの違い.md` に保存された
  - 拒否（`n`）：「PEFTとは何か調べて、学習の記録として保存して」→ 同じように止まり、`n` で保存されなかった。モデルは「保存処理を試みましたが、利用者の確認によりキャンセルされました」と答えた
  - 保存を頼まない「PEFTとは？」では、`save_learning_log` は呼ばれなかった
- 気づき・疑問：
  - **docstring の書き方で、承認の仕組みを使わなくなった**。最初は docstring に「保存は取り消しにくいので、実行の前に利用者の承認を求める」と書いた。すると、モデルはツールを呼ばずに、チャットの中で「この内容で保存してよろしいですか？『保存して』とお知らせください」と自分で確認して終わった（2回試して2回ともそうなった）。モデルは docstring を「自分が会話で承認を取る」という指示として読んだと考えられる。「保存の前の確認はこのツールを呼んだあとにシステムが利用者に行うので、会話の中で聞かずに、そのままこのツールを呼ぶ」と書き換えると、すぐにツールを呼び、CLI の `[y/N]` で止まるようになった。docstring はモデルへの指示なので、人間向けの注意書きのつもりで書くと、ふるまいが変わってしまう
  - **承認の前後で `usage` が分かれる**。承認のあとの `run_sync` は別の実行なので、そのままでは `[usage]` に後半の `requests=1` しか出なかった。2回目の `run_sync` に `usage=result.usage` を渡すと、合計（`requests=3`）が出るようになった
  - **見出しが2つ並んだ**。モデルは本文の先頭に `# 題名` を書くことが多く、ツール側でも見出しを付けていたので、保存したファイルに見出しが2つ並んだ。本文に見出しがあればそれを使うようにした
  - 疑問：承認待ちで止めるのは、CLI のように同じプロセスで聞ける場合は簡単だった。Web アプリのように、承認が何分もあと（別のリクエスト）で返ってくる場合は、`all_messages()` をどこに保存して、どう再開するのがよいか
